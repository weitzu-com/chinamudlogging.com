# ChinaMudLogging：Ego Lite 七语线上验收

验收日期：2026-11-05；环境：SiteGround WordPress 正式站 `https://www.chinamudlogging.com/`。浏览器：Ego Lite 0.6.2.5，单一 TaskSpace 9，串行导航。检查快照以随附 URL 台账为准；站点同时存在其他会话的内容更新。

## 本次问题与修复

| 问题 | 影响 | 最终处理 |
|---|---|---|
| UTF-8 字节长度被当作姓名等字段的字符长度 | 有效中文、阿拉伯语内容会被提前拒绝 | 服务端按 UTF-8 字符计数；保留总请求字节上限与真实字段长度上限 |
| 浏览器字段长度统一为 150，与服务端不同 | 国家允许过长，产品名称被提前截断 | 按字段设置：姓名 160、邮箱 254、公司 200、国家 120、产品 300 |
| 小屏表单字号为 14.4px | 移动浏览器聚焦时可能放大页面 | 700px 以下筛选与询价输入字号设为 16px |
| 首页自动推荐最新入库产品 | 原始目录名称挤掉已核验的多语重点产品 | 七语首页固定查询已审校的十个来源产品，按当前页面语言展示 |
| 手机菜单标记与标签折行 | 西班牙语、俄语、法语菜单出现两行 | 菜单保留自身宽度，标记与标签不折行；七语各重测一次 |
| 输入框边界偏浅 | 白底上的边界对比不足 | 边框由 `#a8b8c2` 改为 `#718390`，对白底对比由 2.04:1 提高到 3.92:1 |
| 产品名称直接拼入查询串 | `in&out` 截断，`4HS+` 丢失加号，`<42V` 丢失比较符 | 链接编码原始产品名称；保存时保留经过标签清理后的技术文本符号 |

运行代码仅更改业务插件的 `inquiries.php`、`render.php` 与主题的 `assets/site.css`；原有用户、邮件凭据、防滥用、DNS、HubSpot 配置保持原样。首页推荐范围不代表其余目录产品已完成全文人工审校。

另对额外目录记录的 77 个夹中文标题、5 个多余空白标题、243 条英文摘要按受控术语表修正，未改变正文及技术字段；逐项原文、译文和修正/回滚脚本见 `wordpress/corrections/english-catalogue-names-20261105.json` 与 `apply-english-catalogue-names.php`。原字段另存各产品的私有元数据归档。全量预检检查并发编辑；分两批生产回查 77+166 条记录的正文、URL、发布日期、图片、分类及技术字段指纹均保持一致。再次运行全部 243 条均已在目标状态，不产生重复变更。

术语处理：立压使用 Standpipe Pressure，悬重使用 Hookload；原始 `100p`、`400r`、`10D`、防爆代码等不推断单位、不补写认证。无法确定具体机械结构的“顶丝”保留为 Dingsi 并标为来源名称，不能据此宣称某种扭矩测量结构。

### 真实询价链路

七种语言分别从 CNPS-ML-B11 产品页面进入询价，保留产品名称；通过真实按钮提交 TEST ONLY 测试数据。各有一条数据库记录与 HTTP 201 回执。相同请求重放均返回 HTTP 200 及原回执；数据库中测试标记对应记录恰为七条，无重复。

七封通知均由收件方 Zoho SMTP 日志确认：`delivered`、`MAILBOX DELIVERY`、`isSpam=No`，按唯一 CML 回执 / Message-ID 对应。WordPress 的 `transport_accepted` 单独只代表邮件传输接受，本次另有实际邮箱投递证据。中文测试姓名为 60 字符，阿拉伯文为 100 字符。

符号修复后另增加一条真实边界询盘，`100℃<42V 4-20mA 1%FS ia J` 产品名称与包含 `<42V`、`+`、`&` 的需求正文均逐字与数据库对照一致，仅生成一条记录；第八封本站通知同样由收件箱投递日志确认。生产邮件类型为 `text/plain`、字符集 `UTF-8`，没有把技术比较符当作邮件 HTML。合计本站八条测试询盘，另有一条 HubSpot 表单测试，均不计作真实客户询盘。

可选 HubSpot 英文表单通过官方 iframe 的实际 Submit 按钮提交，观察到成功提示，并用 CRM 精确匹配测试邮箱确认一条联系人：[测试 CRM 记录](https://app.hubspot.com/contacts/25732190/record/0-1/913571364072?utm_source=app_12360546_mcp&utm_medium=ai_agent&utm_campaign=search)。收件方日志在提交后约七秒出现该 ChinaMudLogging 表单通知，投递至 `sales@cnps.com`，非垃圾邮件；此通知按表单名和时间窗口关联，未读取邮件正文。各语言的本站原生表单保持可用；HubSpot 可选表单明确标为英文。

必填与错误邮箱校验七语通过。分析请求检查未发现测试邮箱或需求正文。所有测试均标明 TEST ONLY / NO SALES FOLLOW-UP；不得计为真实商业询盘。

### 故障及边界测试

`python3 wordpress/tests/run-ego-qa.py` 在一次性 WordPress 数据库中执行，15/15 通过：有效中文姓名、阿拉伯文姓名、重复回执、超长拒绝、国家/产品字段上限、邮件失败仍保存并标记、显式重发、首页推荐不会受最新目录入库干扰、特殊技术符号的链接及保存，以及 243 条文案修正的全量预检、技术字段保护、幂等和回滚。邮件失败通过隔离环境模拟，未关闭生产邮件。GitHub Actions 还执行 PHP/JS 语法、内容/译文完整性、匿名测量、目录结构化数据/边界测试及打包。

保留失败证据：新增特殊符号测试初次为 13/15，链接编码与服务端技术文本保存修正后为 15/15。扩展目录文案夹具时还发现 WordPress 的默认文本过滤会把原始 `<42V` 视作标记；修正脚本仅在 SSH/CLI 的已预检写入期间保留这些原始字节，并在 finally 中恢复原过滤器。243 条完整应用、再次执行和回滚均在隔离环境验证后才用于生产。
