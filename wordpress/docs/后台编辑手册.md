# 后台编辑与询盘处理

正式后台使用本站 WordPress 管理员账号。账号密码不保存在本文；预览访问凭据在本机私有缓存 `~/.cache/chinamudlogging-wordpress/preview-access.json`。

## 编辑产品

1. 在 Products 打开产品，确认右侧语言。英文产品保留原 slug，避免修改已有 URL。
2. 原生区块正文包含用途、参数表和来源说明。改技术参数前先核对供应商原始资料，不将目录声明当作认证证明。
3. Product configuration 保存型号、重量、信号、量程、接口。Structured source specifications 独立保存参数名、原始值、数值表达、单位；范围和精度保留原写法，不推断单位。后台结构化字段与正文规格表都须随经确认的变更同步更新。
4. 图片在 Featured image 中选择。下载文件通过原生 File 区块或正文链接上传，确认可下载后发布。
5. Polylang 语言栏关联同一产品的译文。首期六语产品为选型摘要＋核对后的重点参数＋完整英文资料链接，全文机器译稿仍待专业审核。
6. 新译文先保存草稿；确认术语、型号、单位、资料链接与 RTL 后再发布。草稿不会出现在公开语言切换或 sitemap 中。

## 页面、导航与外观

Pages 编辑公司、服务、隐私等原生区块。Appearance → Editor 编辑区块主题模板与模板部件；七语导航和产品列表由 Core 插件按当前语言生成。没有对应译文的产品不生成空白页面。Insights 首期仅英文。

产品分类由 Product families 管理，保持五类及其 Polylang 语言关联。更换主题不会删除产品、字段和询盘表。

## 处理询盘

Inquiries 仅管理员可见，按时间展示回执、语言、需求及通知状态。`transport_accepted` 表示传输接受，实际送达仍以收件箱或 Zoho 投递日志为准。`failed`、`queued`、`notification_disabled` 会触发后台提醒，先处理已保存的需求，再检查邮件配置。测试数据均有 TEST ONLY 标记，已确认的强制失败演练标记为 `test_failure_verified`。

通过回执对应邮件 Message-ID：`<cml-回执UUID@chinamudlogging.com>`。不要把客户邮箱、询盘正文、公司或电话写入分析事件。本站不自动删除客户记录；管理员应按实际业务留存规则管理并备份。

## 再次导入

来源 ID＋语言确定产品/文章唯一身份；媒体按 SHA256 去重。重复导入不会增加重复记录。后台改过标题、正文、摘要或结构化字段后，导入会停止并提示 Editor changes detected。先导出备份、比较来源与人工变更，确认合并结果后才使用 `--overwrite-edits`；不能把这个参数当作常规重跑选项。

## 日常维护

只保留单一 Yoast SEO、免费 Polylang、Core 业务插件、WP Mail SMTP 和 SiteGround 官方必要插件。更新前备份，更新后检查英文与阿拉伯语产品、七语询价和 sitemap。表单 API `/wp-json/cml/v1/*` 不应缓存。预览域名始终保留访问保护；它与正式域名共用数据库。
