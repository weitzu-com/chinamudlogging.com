# 旧链接查询参数保留

72小时复查发现：现有 `/shop/` 等旧路径能301到对应内容，但旧处理器丢弃查询参数。实际 `/shop/?q=ALS+2.2&utm_source=cml-72h` 最终变成不带查询的 `/product/`；直接访问新目录同一查询则有筛选结果。此问题影响旧链接的搜索、产品及来源上下文，不是Google未收录的已证明原因。

新增独立MU `wordpress/extensions/cml-legacy-query.php` 1.0.0，在原处理器之前仅处理既有 `cml_redirects` 中携带查询且目标为本地普通路径的条目。保持原始查询顺序、重复参数、加号、百分号编码及阿语文字编码；不改重定向表、正文、媒体、sitemap或无查询请求。不接受外部/协议相对目标、原始换行；含目标查询或片段的未来规则继续交给既有处理器。最后使用WordPress原生 `wp_safe_redirect`。

隔离真实WordPress运行45个场景，覆盖8条既有规则、搜索/产品/来源参数、重复参数、编码、同域301、无查询、不匹配路径及不安全目标。运行：

```sh
python3 wordpress/tests/run-legacy-query.py
```

生产发布前先核对文件不存在、现行映射未被覆盖，备份MU目录到文档根目录外。仅安装新增文件，通过PHP语法检查、清除SiteGround缓存后，复测8条规则有/无查询两种情况及真实搜索结果一致性。保留修复前失败记录，不覆写为首次通过。

回滚：先核对生产文件哈希仍为本次版本，再把该独立MU移到文档根目录外并清缓存；不回滚整库、不改映射、不覆盖并行插件或新询盘。本轮运行证据与备份在私有 `~/.cache/chinamudlogging-wordpress/postlaunch-20261107T073420Z/`，公开仓库只保存技术实现与测试。
