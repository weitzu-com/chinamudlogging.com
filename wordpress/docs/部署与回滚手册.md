# ChinaMudLogging WordPress 部署与回滚

以 `验收报告.md` 为当前验收真相来源；源码检查、预览验收和正式切换分别记录。

## 产物与来源

- `theme/cml`：原生区块主题；`plugin/cml-core`：独立产品、询盘和导入业务插件。
- `migration/`：受控内容台账、URL 映射、七语页面文案、重点产品译稿。完整机器译稿 `review: pending` 不发布。首期使用 `priority-localizations.json` 的六语选型页，包含核对后的来源参数与完整英文资料链接；不描述成全文翻译。
- 构建目录：`~/.cache/chinamudlogging-wordpress/`，不提交缓存、ZIP、源内容归档和媒体副本。
- 原始公开内容记录随迁移包保存到 `source-archive.json`；不得将迁移包或归档放在网站可公开下载的目录。
- 当前在 `codex/wordpress-migration` 分支。保持原 Astro 生产站运行，通过现有 PR 流程评审改动。

## 重建与本地验收

运行 `python3 wordpress/scripts/prepare.py --live` 生成校验和与线上对账结果。运行 `python3 wordpress/scripts/check-bundle.py` 验证内容和译稿数值。

首次预览需从 WordPress 官方下载 Polylang **3.9.1** 到 `~/.cache/cml-wordpress/polylang`。`python3 wordpress/scripts/local-preview.py` 启动真实 WordPress Playground，监听 `127.0.0.1:9400`，使用 PHP 8.3 与 SQLite。

预览数据库是隔离、临时的；测试脚本会模拟邮件发送并仅在此临时数据库发布待审内容供视觉检查。不得将预览数据库恢复到生产。测试不证明 SiteGround 的 MySQL、SMTP 或邮箱送达。

另一个终端运行 `python3 wordpress/scripts/http-audit.py`，检查所有英文内容路径、分类、旧重定向及六语首页。完成后运行 `python3 wordpress/scripts/package.py`，产物在缓存目录的 `release/`。

## SiteGround 新建与安装

1. 在现有套餐中新建**独立空白站点＋临时域名**，记录站点 ID、SSH 主机、站点目录和临时 URL。不要复用 ifgs.com、cnps.com 等现有站的目录。
2. Site Tools 为临时站启用服务器访问保护和 HTTPS；`blog_public=0` 只是禁止索引，不代替访问控制。
3. 安装受支持的 WordPress 与 PHP 8.2+。数据库与管理员凭据在主机本地配置，禁止写进 Git、报告或聊天。服务器安装后运行 `wp core verify-checksums`。
4. 安装本包主题与插件、免费 Polylang 3.9.1、单一免费 Yoast SEO、SiteGround 官方 Speed Optimizer、免费 WP Mail SMTP。不要同时启用其他 SEO 或整页缓存插件。
5. 激活 Polylang 与 cml-core，再运行 `wp eval-file /private/path/setup-languages.php --path=/target/public_html`。脚本使用经 3.9.1 源码核验的 Polylang 语言接口；升级版本须先回归测试。
6. 解压内容包到站点 document root **之外**。备份目标数据库及文件，再运行 `wp cml import /private/path/cml-migration/bundle.json --path=/target/public_html`。
7. 首次导入只发布英文，其他语言为草稿。第二次运行导入，确认内容和附件计数不变。碰到 slug 冲突或媒体校验失败必须解决再继续。
8. 激活 cml 主题，检查首页、文章列表、产品和分类路由。移除新安装自带的示例页面前，先确认其为可处置样例；不清除原站业务数据。
9. `--publish-reviewed` 只发布 bundle 中已批准的页面与重点产品选型内容。完整机器译稿保持 pending，不绕过技术审核直接替换公开规格。

## 询盘通知与验收

- 默认保存询盘但关闭通知，状态为 `notification_disabled`。后台 **Inquiries** 仅管理员可见。
- 本次自动化使用 WP Mail SMTP 的 `mail` 传输，由 SiteGround 本地邮件服务提交，配合本站 DKIM 签名；不是使用外部账号密码的 SMTP。匿名 localhost SMTP 的实测提交被拒绝，未沿用该失败配置，也未复制其他站点密码。
- `sales@chinamudlogging.com` 已核实为现有 Zoho Sales 邮箱的别名，无须创建转发、委托或新邮箱。收件以 Zoho 管理端投递记录为依据。
- DKIM 私钥在 document root 外的 `.cml-mail/`，权限 0600。选择器 `cml20261104` 的公开 TXT 与既有 Zoho 邮件记录并存。现有 SPF 保留；已核验邮件为 SPF soft failure、DKIM 对齐通过、DMARC 通过，不能描述成 SPF 全通过。
- 核实 `sales@chinamudlogging.com` 的归属、发信域和真实收件能力后，使用 `wp option update cml_recipient sales@chinamudlogging.com` 与 `wp option update cml_mail_enabled 1` 开启通知。
- 七语各提交一个带唯一标识的测试询盘；在 WordPress 数据库和真实收件箱中逐项核验，包括垃圾箱。`transport_accepted` 只是邮件传输接受，不能作为已送达证据。
- 重复提交返回同一回执且只保存一次；模拟传输拒绝时，数据库记录必须保留为 `failed`。恢复后由管理员核对保存记录，再在受控 WP-CLI 调用 `cml_dispatch_inquiry(ID)` 显式补发并核对收件。正常重复提交不会再次发信。`mail-acceptance.php` 只重放 TEST ONLY 测试记录，不用于真实客户。
- 对 CDN / Speed Optimizer 排除 `/wp-json/cml/v1/*` 的缓存。表单临提交获取新 token，防止页面缓存造成过期 nonce。
- 不向分析系统发送客户信息。上线前确定业务留存周期，安排管理员定期清理；当前版本不会自动删除客户询盘。

## 正式切换

1. 导出并保存原 DNS 区域、A/AAAA/CNAME、MX、TXT、SPF/DKIM/DMARC、CDN 设置及现有重定向；不得覆盖邮箱配置。
2. 冻结内容，重新运行线上对账并导入最后增量；记录完整内容包 SHA256。
3. 对新站数据库及文件作站外备份，在另一个受保护实例演练恢复，核对首页、产品、附件及询盘表。未演练不签署该验收项。
4. 确认正式域名在 SiteGround 可用并已签发有效证书；按实际 DNS/CDN 架构准备主机绑定。避免指向未配置完成的服务器。
5. 使用 WP-CLI `search-replace` 先 `--dry-run`，再替换临时域名为正式域名，跳过 `guid`；备份保留在站外。检查序列化数据、媒体和语言链接。
6. 根域及 HTTP 单跳 301 到 HTTPS www，并保持路径与查询串。按 `url-map.csv` 实测旧路由，不将失效产品批量转到首页。
7. 测试通过后修改网站所需 DNS，保留邮件记录。通过 `cml_production_released=1` 仅开放 www/根域，`blog_public=1`；MU 插件继续保护 preview 并强制禁止索引和不缓存。preview 与正式站共用数据库，编辑会同时影响正式内容，不作为隔离试验数据库。
8. 当天、72 小时、第 7 天检查 HTTP 错误、询盘、邮件送达、搜索控制台与索引。后两次检查属于未来验收，不能提前标记通过。

## 回滚

保留原 Astro 托管和内容至少 30 天。新站出现持续 5xx、关键旧 URL 失效或询盘无法保存时，暂停内容编辑并导出切换后的询盘，恢复原网站 DNS/CDN 指向；不回滚 MX/TXT 邮件记录。

保留新 WordPress 数据库及文件用于诊断和询盘追补。DNS 回滚存在缓存传播时间，不承诺瞬时完成。恢复后验证原站与邮件，记录故障、回滚时间和遗留询盘。
